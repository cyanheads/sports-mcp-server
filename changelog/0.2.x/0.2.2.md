# 0.2.2 — 2026-09-21

## Changed

- **`createApp({ sessionMode: 'stateless' })` declares the HTTP session posture in source** ([#12](https://github.com/cyanheads/sports-mcp-server/issues/12)) — with `MCP_SESSION_MODE` unset or blank, the transport now serves stateless by source-level default instead of falling through to the schema's `auto` (stateful). An explicit `MCP_SESSION_MODE=stateful` or `auto` still overrides it, and stdio is unaffected.
- **Server `instructions` rewritten** as two agent-facing sentences: call a league-keyed tool directly, or resolve a team or player first when its ID is unknown.
- **Argument rejections carry `data.reason: "invalid_arguments"` and a `Recovery:` hint** naming the tool's accepted keys (cyanheads/mcp-ts-core#445); tool error text now closes with `(reason <reason>)` (cyanheads/mcp-ts-core#458); a case-folded argument key (`League` → `league`) is accepted (cyanheads/mcp-ts-core#452); `/.well-known/mcp.json` publishes the resolved session mode under `_meta["io.github.cyanheads.mcp-ts-core/sessionMode"]` (cyanheads/mcp-ts-core#387).
- **Output schemas render nullable fields as `"type": ["string", "null"]`** instead of an `anyOf` of two types (zod ^4.4.3 → ^4.6.5's `toJSONSchema`); the `tools/list` contract is otherwise unchanged.
- **README restructured** into an Overview and a per-tool Capability reference section; developer protocol docs (`CLAUDE.md`/`AGENTS.md`) gained a session-posture/shutdown section and a Publishing section documenting the release PR flow.
- **Framework skill tree moved** `skills/` → `framework-skills/` (cyanheads/mcp-ts-core#428) so a plugin-shipping server no longer hands its development skills to every installing agent; the new `release-pr-review` skill is included.
- Repo hygiene: `audit:fix` script (cyanheads/mcp-ts-core#363), a bunfig `minimumReleaseAgeExcludes` hold for first-party framework releases, the scaffolded `.github/workflows/codeql.yml`, and a CONTRIBUTING/issue-form/plugin-manifest refresh.

## Fixed

- Bun engines floor raised `>=1.3.0` → `>=1.4.0`, matching the framework's own floor (cyanheads/mcp-ts-core 0.12.9).
