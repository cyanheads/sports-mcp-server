# 0.2.3 — 2026-09-30

## Changed

- **`format()` text** flattens CR/LF inside provider-supplied values in all seven tools and wraps the full player biography in a code fence longer than any backtick run it contains. `structuredContent` values are unchanged, and the server `instructions` now state that provider content is data.
- **`player_not_found` and `team_not_found` recovery hints** come from the framework's contract default instead of `ctx.recoveryFor()` at each throw site.
- **Docker image** cross-installs production dependencies on the build platform (`--os`/`--cpu`) and installs the framework's 13 OpenTelemetry peers at their declared ranges through `scripts/install-otel.ts`, up from a hand-listed 10.
- **Packaging** — npm `files` excludes `dist/*.mcpb`, `.mcpbignore` excludes `docs/idea.md` and `logs/`, and `manifest.json` `author` drops `email` and `url`.
- **Framework sync** — `framework-skills/` and the synced scripts match mcp-ts-core 0.13.10: `lint:packaging` gains checks 13–15 (npm `files` bundle exclusion, `manifest.json` version parity, Dockerfile build platform), `lint:mcp` fails on a definition that cannot load, and `release:github -- --check` validates the tag annotation.
- **Docs** — README and `.env.example` cover `LOG_TOOL_FAILURE_PAYLOADS`, `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES`, and the OTLP endpoint variables; README and `docs/design.md` describe request bounds, provider routing, and date-range semantics as built, and `CLAUDE.md`/`AGENTS.md` follow the framework's `ctx` and error-contract reference.

## Fixed

- **Provider request deadlines** ([#13](https://github.com/cyanheads/sports-mcp-server/issues/13)) — ESPN, MLB StatsAPI, and TheSportsDB requests abort a stalled header or body after 10 seconds per attempt, inside a 30-second budget per retried operation that ends in `retry_deadline_exceeded`. Caller cancellation stops the request and the backoff with no further attempt.
- **Upstream HTTP errors** ([#14](https://github.com/cyanheads/sports-mcp-server/issues/14)) keep their status-mapped code, `status`, a bounded `body`, and `Retry-After` instead of becoming `ServiceUnavailable`; 400, 401, 403, 404, 422, and 501 fail after one request.
- **ESPN scoreboard 400** no longer reports `invalid_league`; it stays `InvalidParams` with a recovery hint naming `date`, `date_from`, and `date_to`. `sports_find_team` and MLB standings enrichment rethrow input rejections and cancellation instead of returning a partial result.
- **TheSportsDB errors** never carry the API key: HTTP error messages and data replace the configured key with `[redacted]` and omit the URL, and network failures drop the native error text and cause.
