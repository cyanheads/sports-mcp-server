# 0.1.2 — 2026-06-06

## Changed

- **`sports_get_standings` off-season behavior** — empty standings when no `season` is specified now returns `{ standings: [], notice: "Season not currently active…" }` instead of throwing `season_not_found`; the error is reserved for explicit season years that return no data ([#1](https://github.com/cyanheads/sports-mcp-server/issues/1))
- **`sports_find_player` `sport` parameter** — description now states it is an advisory hint for disambiguation; TheSportsDB does not support server-side sport filtering, so all matching players are returned regardless of the value ([#2](https://github.com/cyanheads/sports-mcp-server/issues/2))

## Fixed

- **Recovery hints in `content[]`** — all `ctx.fail()` call sites now pass `{ ...ctx.recoveryFor(reason) }`, so `content[0].text` carries the recovery hint alongside the error message across all 7 tools ([#3](https://github.com/cyanheads/sports-mcp-server/issues/3))
- **`sports_find_team` ID dedup** — deduplication rewritten from `Set`+`filter` to a `Map`-merge; `espnId`, `mlbId`, and `tsdbId` from subsequent records are merged into the canonical entry via `??=` so cross-source IDs survive instead of being dropped ([#4](https://github.com/cyanheads/sports-mcp-server/issues/4))
- **`sports_find_team` MLB source for `league: "mlb"`** — MLB StatsAPI is now also queried when `league: "mlb"` is specified (previously only ran without a league filter), ensuring `mlbId` participates in the merge for MLB team lookups ([#4](https://github.com/cyanheads/sports-mcp-server/issues/4))

## Dependency bumps

- `@types/node` ^25.9.1 → ^25.9.2
