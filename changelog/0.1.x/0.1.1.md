# 0.1.1 — 2026-06-05

Initial public release of `@cyanheads/sports-mcp-server`. Provides 7 MCP tools over [ESPN](https://www.espn.com/), [MLB Stats API](https://statsapi.mlb.com/), and [TheSportsDB](https://www.thesportsdb.com/) for live scores, schedules, standings, and team/player data across NFL, NBA, MLB, NHL, and major soccer leagues.

## Added

- **`sports_find_team`** — resolve a team name or partial name to its canonical record and source IDs (ESPN + MLB); required before any team-scoped query
- **`sports_find_player`** — search for a player by name across TheSportsDB; returns canonical ID for use with `sports_get_player`
- **`sports_get_scores`** — live and final scores for a league on a given date (ESPN for most leagues, MLB Stats API for MLB)
- **`sports_get_schedule`** — team or league schedule over a date range; supports all 13 league slugs
- **`sports_get_standings`** — current standings or league table by season (ESPN + MLB Stats API)
- **`sports_get_team`** — team detail including roster, recent results, and next fixtures (ESPN + TheSportsDB)
- **`sports_get_player`** — player bio, position, and career metadata from TheSportsDB
- **ESPN service** (`espn-service.ts`) — covers scores, schedules, standings, and team search for 13 leagues via ESPN site API
- **MLB Stats API service** (`mlb-service.ts`) — scores, schedules, standings, and rosters via the MLB Stats API
- **TheSportsDB service** (`thesportsdb-service.ts`) — player and team metadata search; defaults to public test key `3`, supports paid key via `THESPORTSDB_API_KEY`
- **`LEAGUE_ROUTES`** and normalized type set (`NormalizedGame`, `NormalizedTeam`, `NormalizedPlayer`, `NormalizedStanding`) in `services/types.ts`

## Security

- **Input length caps** — `query`, `sport`, `team_name`, `player_id`, and related string inputs bounded by `.max()` validators (50–200 chars) across all 7 tools to block oversized upstream forwarding
- **Date and season regex validation** — `date`, `date_from`, `date_to` fields validated against `^\d{4}-\d{2}-\d{2}$`; `season` against `^\d{4}$` — rejects free-form strings that could be injected into URL query parameters
